## 3. Target A — root cause

`defabricate_llm_answer()` strips a narrow set of past-tense completion verbs and only when the owner's text hints at an action. The V1 live matrix showed the same fabrication in other shapes with **no action routed or executed**:

- **RY5** — "Ping me in a minute so I remember to stretch." → LLM answered "I'll ping you in 60 seconds" (a future commitment; nothing scheduled).
- **UA2** — an invented "Action Taken:" narration block.

The LLM's own sentence is not evidence that anything happened. Both conversational surfaces (`commands._llm_answer`, `Governor._answer_conversationally`) returned model text without checking it against execution/scheduling state.

## 4. Target A — repair and evidence

Extended the existing anti-fabrication seam (`core/security/anti_fabrication.py`) with `remove_unsupported_action_claims(response, action_evidence)`:

- Shape-based, not a phrase blacklist: first-person / VECTOR subject + action verb in past, progressive or future form; a small set of "the deployment is running"-style state claims; "Action Taken:" headers.
- Each claim is checked against **authoritative evidence records** `{action_type, status, scheduled}`. Success statuses only (`ok/executed/completed/success/scheduled`); a future commitment additionally needs scheduling state; matching uses 5-char stems + small synonym families.
- Guards preserve advice and hypotheticals: negation guard, a hypothetical guard that only applies *before* the claim match, and ambiguous verbs (create/save/set/…) that need an action-object noun.
- On a pure-text path the evidence is `[]` (nothing can have run), wired into both conversational surfaces. An "Action Taken:" header returns an honest capability reply; unsupported sentences are dropped and a one-line honest note appended; clean text is returned unchanged.

Evidence:
- 24 tests (`tests/test_pre_rgd2_a_action_claims.py`, GREEN): reminder promise, "Action Taken" block, "I've sent the email", "I'll send it shortly", "The deployment is running", evidence-backed completion and future commitments, unrelated/failed evidence not licensing claims, 6 advice/hypothetical cases preserved, 6 ordinary-conversation cases preserved, and wiring tests through both conversational paths. The action-state check is real, not mocked.
- Also replayed over 17 real conversational replies captured earlier (changed only the 2 fabricated ones).
- **Live (frozen probe A1)** — server log `00:52:21.355`: `removed unsupported action claim(s) (no matching execution/scheduling evidence): ['I’ll ping you in **60 seconds**—stretch now if you’d like!']` — the exact RY5 fabrication. ## 5. Target B — root cause

Two independent seams, traced before any edit:

1. **Transport** — `ResearchHub.search_arxiv` called `http://export.arxiv.org/api/query`. Live raw check (2026-09-21T19:25:39Z): HTTP → `301`, body length 0, `Location: https://…`; HTTPS → `200`, 3,342 bytes. `ET.fromstring("")` raised, was swallowed by the bare `except`, and `[]` came back — only the honest-failure branch of T1 was ever reachable.
2. **Evidence shape** — `Governor.dispatch` can pick either agent that declares `search_arxiv`. `PaperReader` returns evidence under `papers`; `ResearchHub.run` under `results` (authors as a list, plus `published`). The owner-path renderer read only `papers`, so even with HTTPS fixed a ResearchHub answer would have rendered as "no results".
3. **Found by the post-probe live in-process check (correction pass)** — the topic was sent as an unquoted `ti:X OR abs:X`. arXiv does not parse a multi-word topic that way; real retrieval succeeded but returned the **newest papers of any subject** (physics: AdS₅ black holes, neutron stars, etc. for a RAG query). Real evidence not about the topic is not grounding.

## 7. Target C — root cause

F3 (owner-routing closure) moved the ~100 s embedding bootstrap into a shared background `asyncio.Task`, but `IntentMatcher._embed()` still called the **synchronous** `ollama.Client(...).embeddings()` directly inside `async def`. A blocking call inside a coroutine never yields, so the "background" task froze the whole event loop: uvicorn began listening only after all 499 embeddings finished (observed twice previously: 0 HTTP lines between prewarm start and "Uvicorn running"; listener ≈2 min after process start). This **corrects** the earlier OWNER_ROUTING_CLOSURE report's attribution of the delay to "unrelated infrastructure" (already corrected in the V1 report). The F3 unit tests missed it because they mocked `_embed` with `await asyncio.sleep`, which yields.
