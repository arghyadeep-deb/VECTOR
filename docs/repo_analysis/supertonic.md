# supertonic — Absorption Analysis
**Verdict:** UPGRADE (better live TTS) — Supertonic 3 is a genuinely better *live-conversation* engine than Kokoro (smaller, faster, CPU-only, 31 langs incl. HI/JA), and should be absorbed as a config-selectable live-TTS engine that can supersede Kokoro. It does **not** touch the cloning role (Kokoro→live, VoxCPM→cloning still holds; Supertonic competes only with Kokoro).

**What it is:**
- **Model size:** ~99M params, ONNX assets ~260MB download (`README.md:25,286`; `py/example_pypi.py:3`). 5–8x smaller than Kokoro's class is wrong-direction — actually comparable; but ~20x smaller than VoxCPM2's 2B/8GB.
- **VRAM/CPU:** Runs entirely on **CPU, no GPU required** — designed for Raspberry Pi / e-readers / browsers (`README.md:26,278`). README explicitly notes the open-weight fixed-voice path "does not require a GPU." Python SDK GPU mode is **not yet supported** (`py/README.md:144`) — so it is a CPU engine today, which on the RTX 5070 Ti box means **zero VRAM cost**.
- **Latency:** "fast enough to turn an entire webpage into audio in under a second"; avg RTF ~0.3x on an e-reader in airplane mode (`README.md:23,306`). Low-latency real-time synthesis is the headline claim. Quality/speed knob: `total_steps` 5–12 (default 8), `speed` 0.7–2.0 (`README.md:76-77`).
- **Languages:** **31** — including **Hindi (`hi`)** and **Japanese (`ja`)**, plus a language-agnostic `lang="na"` mode (`README.md:31-35`). **No Bengali, no Assamese** in the list.
- **Cloning:** The open repo is **fixed-voice only — no official cloning pipeline** (`README.md:290`). Custom voices come from the hosted "Voice Builder" web tool, which emits a version-specific voice-style JSON you load locally (`README.md:290`, `py/example_onnx.py:95`). Zero-shot cloning exists only in their paid cloud API. So locally it is a *preset/JSON-voice* engine, not a clone-from-WAV engine.
- **Audio:** 44.1kHz 16-bit WAV direct, plus 10 inline expression tags (`<laugh>`,`<breath>`,`<sigh>`) (`README.md:27-28`).
- **License:** **MIT** for code (`LICENSE:1`); **OpenRAIL-M** for model weights (`README.md:524`). Code is fully absorbable; OpenRAIL-M is a responsible-AI use-restriction license (not OSI-free but permissive for VECTOR's single-owner local use) — verify the use-restriction clauses are acceptable, no copyleft on VECTOR code.
- **Python deps:** dead simple — `onnxruntime`, `numpy`, `soundfile`, `librosa`, `PyYAML` (`py/requirements.txt:1-5`). Far lighter than VoxCPM's funasr/modelscope/gradio tree. Also ships `supertonic serve` — a local HTTP server with native `/v1/tts` + OpenAI-compatible `/v1/audio/speech` (`README.md:40,89-98`).

**VECTOR already has:**
- `core/voice/tts.py` — Kokoro-ONNX primary for live conversation (GPU fp16, 0.85x British `bf_emma`); voice map en→bf_emma, hi→hf_alpha, ja→jf_alpha; bn/as degrade to gTTS→pyttsx3 (`tts.py:32-44,107-139,199-206`). Streaming chunker already built (`tts.py:50-70,288-302`).
- `core/voice/cloning.py` — `VoiceCloner` (Chatterbox, CUDA) with `available()`/`synthesize()`/`synthesize_long()` and a **`get_cloner()` factory dispatching on `CONFIG["voice"]["cloning_engine"]`** (`cloning.py:101,144,179,240,307-316`).
- `core/voice/elevenlabs_tts.py` + ElevenLabs streaming in tts.py (`tts.py:364-396`) — cloud fallback, local-first via `prefer_local_voice`.
- `core/voice/language_detector.py` — HI/BN/AS/JA/EN detect + voice map (`language_detector.py:9-31`).
- VoxCPM2 **planned** as the cloning/multilingual upgrade that *supersedes Chatterbox, keeps Kokoro for live* (`docs/repo_analysis/VoxCPM.md:2,29-30,44`).
- Config seams: `CONFIG["voice"]` has `kokoro_model_dir`, `kokoro_speed=0.85`, `sample_rate=16000`, `cloning_engine`, `prefer_local_voice`, `default_voice_profile` (`core/config.py:180-202`).

**Where Supertonic fits (or doesn't):**
- It fits the **LIVE-conversation slot — head-to-head with Kokoro, not VoxCPM.** Both are small ONNX preset-voice engines; both do zero-WAV-reference fixed-voice synthesis. That is a true duplicate of *role*, so this is a Kokoro-vs-Supertonic decision, not an additive gap.
- It does **NOT** fill the cloning slot: no local clone-from-reference pipeline (`README.md:290`). VoxCPM remains the planned cloning engine. Supertonic and VoxCPM do not overlap.
- Why Supertonic can beat Kokoro for live: (1) **CPU-only / zero VRAM** — on a 12GB card where `vector-focus` wants permanent residency and `OLLAMA_MAX_LOADED_MODELS=1`, a live TTS that costs *no VRAM at all* is strictly better than Kokoro's fp16-GPU path competing for VRAM; (2) sub-second / RTF~0.3 latency claim matches or beats Kokoro; (3) **31 languages from one ONNX** vs Kokoro's 3 wired voices + gTTS-cloud crutch for bn/as — removing the gTTS network dependency for hi/ja is a privacy + offline win; (4) 44.1kHz vs Kokoro's 16kHz output; (5) superior text normalization (currency/phone/units beat ElevenLabs/OpenAI per `README.md:344-348`); (6) drop-in OpenAI-compatible `/v1/audio/speech` server.
- The one thing Kokoro has that Supertonic lacks locally: the **British `bf_emma` "VECTOR voice"** identity. Supertonic's local voices are M1–M5/F1–F5 presets + Voice-Builder JSON — owner would need to pick/build an equivalent persona voice.

**Multilingual reality:**
- **Hindi:** Supertonic 3 CER **5.34** on Minimax-MLS (`README.md:246`) — competitive with VoxCPM2 (5.85) and far better than VECTOR's current hi path (Kokoro `hf_alpha`, quality unmeasured, or gTTS cloud). This is a real upgrade for hi and removes the cloud round-trip.
- **Japanese:** CER **4.61** (`README.md:249`) — usable, slightly behind Qwen3-TTS/VoxCPM but local and free.
- **Bengali / Assamese:** **NOT supported** (`README.md:31-33`) — same gap as Kokoro and VoxCPM. VECTOR still needs gTTS-via-Bengali for bn/as regardless. Supertonic does not regress this; it just doesn't help it.
- Net vs VECTOR's needs (HI primary, BN/AS, JA): Supertonic strictly improves HI and JA locally, is neutral on BN/AS. Good enough to lead for hi/ja/en; keep the existing gTTS bn/as fallback untouched.

**Integration plan (if any):**
- **Role:** alternate, config-selectable **live-conversation TTS engine** alongside Kokoro — mirror the cloning-engine pattern exactly. Recommended default flip is owner's call after an A/B listen; ship it selectable, leave Kokoro as default until validated.
- **Create** `core/voice/supertonic_tts.py` — a small `SupertonicTTS` wrapper with the same shape Kokoro is used through: lazy singleton, guarded `import supertonic` (graceful `available()=False` if not pip-installed), `create(text, lang, voice_style, total_steps, speed)` returning `(samples, sample_rate)`. Honor `kokoro_speed`-equivalent + a `supertonic_total_steps` knob. CPU session by default (GPU mode unsupported upstream — `py/README.md:144`).
- **Modify** `core/voice/tts.py` — add a `live_engine` branch in `speak()`/`_speak_kokoro`/`synthesize_to_file`: dispatch on a new `CONFIG["voice"]["live_engine"] = "kokoro" | "supertonic"` via a tiny `get_live_tts()` factory (parallels `get_cloner()` at `cloning.py:307`). No call-site changes elsewhere — reuse the existing `_chunk_sentences` streamer (`tts.py:50-70`) and the bn/as gTTS fallback unchanged.
- **Modify** `core/config.py:180-202` — add `live_engine`, `supertonic_model_dir`, `supertonic_total_steps` (default 8), `supertonic_voice_style` (path to M1.json or a Voice-Builder JSON persona). Map VECTOR lang codes → Supertonic 31-code set (en/hi/ja direct; bn/as stay on gTTS path).
- **Reuse seams (do not duplicate):** the sentence chunker, `sounddevice` playback path, `language_detector.py` lang routing, the lazy-singleton + guarded-import pattern from `cloning.py`. Keep `bn`/`as` on the existing gTTS route in `tts.py:199-206` — do not feed them to Supertonic.
- **VRAM impact:** **zero** (CPU engine). This is the key win on the 12GB card — no contention with `vector-focus` or VoxCPM-on-demand.
- **Tests:** `tests/test_supertonic_tts.py` — `available()=False` graceful path (no dep), engine-factory dispatch, lang-code mapping, bn/as still routed to gTTS, config validation. Synth tests guarded by `available()` like `cloning.py`.
- **Effort:** ~1 focused session for wrapper + factory + config + tests. Owner one-time steps: `pip install supertonic`, ~260MB model download, and picking/building a persona voice JSON to replace `bf_emma`.

**Recommendation:**
Absorb Supertonic 3 as a **config-selectable live-conversation TTS engine that can supersede Kokoro** — priority **MED**. It is a real upgrade over Kokoro on the dimensions that matter most for this hardware: it is **CPU-only with zero VRAM cost** (decisive on a 12GB card already squeezed by `vector-focus` permanent residency and an 8GB on-demand VoxCPM), it claims sub-second / RTF~0.3 latency, it natively covers 31 languages including a measurably-decent **Hindi (CER 5.34)** and **Japanese (4.61)** with no cloud dependency, outputs 44.1kHz, and has best-in-class text normalization — all under MIT code + OpenRAIL-M weights, fully local, satisfying VECTOR's no-cloud rule. Crucially it does **not** make VoxCPM redundant: Supertonic has no local clone-from-WAV path (Voice Builder is a hosted tool / paid API per `README.md:290`), so the planned division of labor sharpens to **Supertonic = live conversation, VoxCPM = cloning + persona finetune, Kokoro = legacy fallback**. The reasons this is MED not HIGH: (1) the existing Kokoro live path already works and Supertonic's only deficit is lacking the British `bf_emma` identity — losing the established "VECTOR voice" requires an owner A/B and a persona-voice JSON before flipping the default; (2) it does nothing for the Bengali/Assamese gap; (3) OpenRAIL-M's use-restriction clauses should be eyeballed once. So: build the guarded `SupertonicTTS` wrapper behind a new `live_engine` config seam (mirroring `get_cloner()`), keep Kokoro as the default until the owner confirms the voice on a listen, and gate it as a lightweight optional install.
