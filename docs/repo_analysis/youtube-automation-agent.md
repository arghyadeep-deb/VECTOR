# youtube-automation-agent — Absorption Analysis
**Verdict:** IMPLEMENT (gaps) — narrow, low-effort

**What it is:** A Node.js 18+ / Express single-process "set-and-forget" YouTube channel automation system (`darkzOGx/youtube-automation-agent`, **MIT license**). Seven JS agent classes (content strategy, script writer, thumbnail designer, SEO optimizer, production management, publishing/scheduling, analytics/optimization) run a cron pipeline (`schedules/daily-automation.js`) that researches trends → writes scripts → builds thumbnails → optimizes SEO → uploads to YouTube via the googleapis SDK → reads YouTube Analytics. Stack: express, googleapis, openai / @google/generative-ai, sharp/jimp (thumbnails), playwright, sqlite3, node-cron. Despite the "agent" naming, most logic is heuristic/templated, not LLM-driven (e.g. `generateAngle()` picks from a hardcoded array, `seo-optimizer-agent.js` scores with regex rules).

**VECTOR already has:** A complete Python content district covering the same pipeline:
- Script writing: `districts/content/script_generator.py:29` (`ScriptGenerator`, LLM-backed, 4 structures incl. `youtube_tutorial`/`youtube_short`)
- Title/thumbnail concept + tags + scheduling: `districts/content/video_generator.py:175` (`generate_title_thumbnail`), `:254` (`generate_tags`), `:281` (`suggest_scheduling`)
- Full video pipeline incl. AI thumbnail + YouTube/IG upload: `districts/content/video_pipeline.py:317` (`_generate_ai_thumbnail`), `:430` (`_upload_youtube`)
- Upload to YouTube/IG/TikTok via googleapiclient: `districts/content/uploader.py:47` (`upload_to_youtube`, graceful simulated fallback when creds absent)
- Captions: `districts/content/caption_generator.py`; video merge: `districts/content/video_merger.py`; ComfyUI: `districts/content/comfyui_adapter.py`; voice: `districts/content/voice_generator.py`
- Post-publish metrics from YouTube Data + Analytics API and Instagram Graph: `districts/content/analytics_retriever.py:1` (`AnalyticsRetriever`, `PostMetrics` with auto `engagement_rate`)
- Scheduling/state-machine/retry feedback loop: `districts/content/content_scheduler.py:16`, `districts/content/post_job.py` (`PostJobTracker`: PENDING→PUBLISHING→PUBLISHED/RETRYING/FAILED), `districts/content/blog_publisher.py`
- Agency-side strategy: `districts/agency/content_strategist.py:65` (`analyze_trends`), `districts/startups/competitor_spy.py:24` (`analyze_competitor`), `districts/startups/market_scanner.py:61` (`analyze_trends`)

**Overlap %:** ~85%. The entire generate→thumbnail→SEO→upload→schedule→analytics arc already exists in VECTOR, mostly at higher quality (LLM-driven generation + SQLCipher persistence + HP/agent_base + graceful fallbacks + the publish→track→optimize loop in `content_scheduler.py`). The repo's upload, captions, scheduling, analytics retrieval, and script writing are pure duplicates.

**Genuine gaps worth absorbing:**
- **YouTube *trending-topic* harvesting via Data API** — `content-strategy-agent.js:48` calls `videos.list({chart:'mostPopular', regionCode})` to pull what is trending *on YouTube right now* and mine keywords from titles. VECTOR's `analytics_retriever.py` reads metrics for *your own* posts; `agency/content_strategist.py.analyze_trends` is LLM-opinion, not live YouTube data. This regional-trending pull is a real, missing data source. **Python-portable: yes** (same `googleapiclient` already imported in `uploader.py`). **Effort: ~0.5 day.**
- **Competitor channel analysis** — `content-strategy-agent.js:73-155` enumerates a competitor channel's recent uploads (`search.list` + `videos.list`), aggregates view-weighted topic keywords, upload frequency, avg views. `startups/competitor_spy.py` is generic/LLM, not YouTube-specific. **Python-portable: yes.** **Effort: ~0.5 day** (folds into the same module as trending).
- **Deterministic SEO scorer (0–100) + chapter/timestamp builder** — `seo-optimizer-agent.js:476` (`calculateSEOScore`: title length/number/year/power-word, description timestamps/links/format, tag count/long-tail/dedup) and `:408` (`generateChapters` from section durations). VECTOR generates SEO copy via LLM but has **no rule-based scorer to grade/gate** it, and no deterministic chapter builder from script sections. A cheap, free, offline scorer is a useful pre-publish quality gate. **Python-portable: yes** (pure logic, zero deps). **Effort: ~0.5 day.**
- **Heuristic optimal-publish-time picker** — `publishing-scheduling-agent.js:243` (`optimizePublishTimes`/`findBetterTime`). Marginal: `video_generator.suggest_scheduling` (LLM) and `content_scheduler` already cover this. **Skip** unless a free offline picker is wanted (trivial).

Everything else (express server, sqlite3 db, sharp/jimp SVG thumbnail compositing, googleapis upload, cron, OAuth in `oauth-server.js`/`modern-auth.js`, the dashboard HTML) is duplicate or inferior to VECTOR equivalents and must not be ported.

**If UPGRADE — what's better & migration risk:** N/A. Nothing in the repo exceeds the corresponding VECTOR module; the few gaps are *additions*, not replacements.

**Integration plan:**
- New file `districts/content/youtube_trends.py` — class `YouTubeTrendScout(AgentBase)` with `fetch_trending(region: str)` (Data API `chart=mostPopular`) and `analyze_competitor(channel_id)` (search.list → videos.list → view-weighted keyword aggregation). Reuse the existing `googleapiclient` import pattern and credential path already in `districts/content/uploader.py:58-72`; reuse `core.config.CONFIG["api_keys"]` for the key; degrade gracefully (return `{"simulated": True}`) when no creds, mirroring `uploader.py`. Keyword extraction must be reimplemented in Python (the JS `extractKeywords` stop-word filter is trivial logic) — do **not** copy the JS stop-word array verbatim as a "tell"; write a fresh one or reuse any existing tokenizer in `core/`.
- New file `districts/content/seo_scorer.py` — pure-Python `score_seo(title, description, tags) -> dict` (0–100 + breakdown) and `build_chapters(sections) -> list` from script section durations. No external deps. Wire as an optional pre-publish gate inside `content_scheduler.py.schedule_post` / `video_pipeline.py`.
- Seams to reuse: `core.city.agent_base.AgentBase` (HP + ghost), `core.config.CONFIG`, the governor/permission_gateway for any RED upload action (already enforced by `uploader.py`), `content_scheduler.py` feedback loop. No new dependencies (googleapiclient + httpx already present).
- Provenance watch: strip the repo's hardcoded English-only stop-word list, the templated `angles[]` clickbait array, the magic "best publish day/hour" tables, and any `darkzOGx`/`youtube-automation-agent` strings. Use VECTOR logging (`logger.info("[VECTOR][content] …")`), not the repo's chalk/winston style.
- **Total effort: ~1–1.5 days** for two new files + tests, no modifications to existing modules beyond an optional one-line gate hook.

**Recommendation:** IMPLEMENT the narrow gaps only. VECTOR's content district already out-classes ~85% of this repo (LLM generation, encrypted persistence, HP-aware agents, a real publish→track→optimize loop), so the bulk is a duplicate to be left alone. The three additions worth pulling are genuinely absent and cheap: live YouTube regional-trending harvesting and competitor-channel keyword mining (one new `youtube_trends.py` module reusing the existing googleapiclient/credential seam), and a deterministic offline SEO scorer + chapter builder (`seo_scorer.py`) to gate the LLM-generated metadata before upload. Reimplement in Python from the *behavior*, copy no JS, scrub the repo's hardcoded heuristic tables and stop-word lists, and wire through `AgentBase` + `content_scheduler`. Roughly one to one-and-a-half days of work; everything else (server, dashboard, sharp thumbnails, googleapis upload, cron, OAuth) is skipped as inferior duplicates.
