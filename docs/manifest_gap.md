# Manifest Gap Report

Generated by `scripts/manifest_gap.py` — static AST scan of `districts/*/` diffed against `config/agent_manifest.yaml`. A class counts as a real agent if it subclasses `AgentBase` or defines its own `run`/`async run` method (covers orchestrator classes like `OpsSwarm`/`QASwarm` that don't subclass `AgentBase`).

`run() branches?` is a heuristic (looks for `"type"`/`'type'` literals inside the run method's AST) — a hardcoded-output agent (e.g. ignores params) will show `no` and should NOT be registered as-is without a follow-up fix; it will fake-succeed once dispatched regardless of task type.

**Totals: 83 registered / 114 unregistered / 197 real agent classes found.**

`__init__ needs args?` = `yes` means `ManifestLoader.instantiate_all()`'s bare `cls()` call will fail; needs an adapter or default args before registering.

## Triage (manual pass, 2026-06-21)

Of the 114 unregistered classes:

- **15 already reachable** — `OpsSwarm`/`QASwarm` self-load these via `_load_agents()` at `__init__` time (see `districts/ops/agent.py:53-58`, `districts/qa/agent.py:41-52`) and route to them internally by keyword match. Registering them a second time in the manifest would create a duplicate dispatch path and a duplicate HP-economy entry. Not a real gap.
- **42 ready to register as-is** — own `run(task)`, branches on `task["type"]`, zero-arg `__init__`. Mechanical Task A.2 work.
- **46 need a run()-branching fix first** — have a `run()` that takes `task` but doesn't appear to look at `task["type"]` (stock_analyst-style: returns the same thing regardless of what's asked). Registering these as-is repeats the exact governor-reachability bug this whole effort is fixing, just one level down. Needs a per-file fix before manifest entry.
- **1 needs an adapter** — `districts.startups._base.StartupAgentBase`: abstract base class (`__init__(self, name: str)` has a required arg, no own `run()`). Not a real agent — it's what `market_scanner`/`idea_validator`/`competitor_spy`/`revenue_modeler` already extend. Exclude from registration.
- **10 have no `run()` of their own** — AgentBase subclass but only inherits the generic no-op stub. Registering as-is would fake-succeed exactly like the districts this whole project exists to fix. Each needs either a real `run()` written first, or is correctly NOT meant to be governor-dispatched (e.g. `EmergencyResponseSystem` is an event-queue service already started directly by `autonomous_loop.py:1766`, `SubconsciousLoop` is already wired via `cron_jobs.py`'s interval job — both confirmed correctly-wired-elsewhere in the 2026-06-21 audit, not gaps).
