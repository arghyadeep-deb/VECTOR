# Phase 3 Vectorcode Sweep Inventory — 2026-10-08

## Scope and counting method

This is the scoping record for the full-depth `vectorcode/` audit. Counts are
physical files as present on disk on 2026-10-08, not only Git-tracked files.
That distinction matters: the tree contains 11,060 `node_modules` files and
1,673 files below `__pycache__` directories. A directory's count is recursive;
the immediate children of `vectorcode/src/` are therefore disjoint audit units.

The complete tree contains **16,171 files, including 2,133 Python files**.
Applying the classifications below produces:

| Category | Files | Meaning |
|---|---:|---|
| (a) full-depth source | 1,484 | Hand-written runtime/source and compatibility surfaces to audit |
| (b) excluded | 12,935 | Vendored dependencies, generated output, binaries, caches, licences, and product docs |
| (c) ambiguous | 1,752 | Tests, command/rule content, evaluation corpora, recipes, and skill content; do not silently treat as production or discard |
| **Total** | **16,171** | Physical files under `vectorcode/` |

Root-level files are included in the totals but are not subdirectories. The
root contains 12 files; executable/configuration files (`vector.py`,
`session_db.py`, package entry points and manifests) are category (a), while
the comparison/readme documents are documentation context rather than audit
units. `email.db` is a data artifact and must not be treated as source.

## Priority ranking for category (a)

The ordered tiers below are the sweep queue. Ordering is driven by trust
boundary first, then external/money impact, then explicit backlog evidence,
then blast radius. Items on one line are still ordered left-to-right.

1. **Security and authorization boundary:** `src/vc_security`, `src/vc_mcp`,
   `src/security`, `src/sandbox`, `src/gateway`, `src/server`, `src/mcp`,
   `src/tools`, `src/vc_tools`, `src/repl`, `src/workflow`, `src/vc_system`.
2. **External protocols and actions:** `src/channels`, `src/comms`,
   `src/connectors`, `src/a2a`, `src/acp`, `src/acp_adapter`, `src/transports`,
   `src/tui_gateway`, top-level `gateway`, `tui_gateway`, `acp`, and
   `mcp_client`.
3. **Explicit backlog / money / autonomous execution:** `src/agents` (OD-56),
   `src/learning` (OD-18/37), `src/plugins` (OD-49), `src/mining` (OD-55),
   `src/memory` (OD-31), `src/cron`, `src/scheduler`, `src/environments`,
   `src/operators`, `src/system`, `src/migrations`, and `src/cli` (OD-7).
4. **Inference and agent control plane:** `src/agent`, `src/vc_agents`,
   `src/engine`, `src/vc_engine`, `src/providers`, `src/core`, `src/vc_core`,
   `src/hooks`, `src/guidance`, `src/vc_skills`, top-level `engine`, `hooks`,
   `providers`, `plugins`, `tools`, and `code_intel/src` + `scripts`.
5. **Sensitive context and observability:** `src/vc_sessions`, `src/persona`,
   `src/context`, `src/prompt`, `src/telemetry`, `src/traces`, `src/vc_traces`,
   `src/speech`, `src/config`, `src/claims`, `src/intelligence`, `src/scripts`,
   top-level `context`, `migrations`, and `packages`.
6. **Lower-risk presentation/support:** `src/display`, `src/ui`, `src/utils`,
   `src/districts`, `src/neural_training`, `src/bench`, top-level `display`,
   and `vectorcode_cli`.

Ambiguous category-(c) units require a separate provenance/reachability decision
before assignment to the full-depth queue. They are not approved exclusions.
